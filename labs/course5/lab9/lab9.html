Lab 8 – Identify the attack vectors on USB drive

Course 5 - Assets, Threats, and Vulnerabilities

Overview

In this activity, I performed a threat model using the PASTA (Process for Attack Simulation and Threat Analysis) framework. The goal was to determine whether a new sneaker shopping app is safe to launch by identifying business requirements, technical risks, vulnerabilities, and appropriate security controls. This structured approach helps organizations understand how attackers might target an application and what protections are needed before release.

Scenario

I am part of the security team for a sneaker company preparing to launch a mobile app that allows customers to buy and sell shoes. Using the PASTA framework, I evaluated the app across all seven stages to identify risks and define security requirements that protect user data, transactions, and backend systems.

Stage I – Define Business and Security Objectives

The app must support secure and seamless transactions between buyers and sellers. It must protect user account data and payment information in compliance with industry privacy standards. Additionally, the app must maintain reliability and uptime to support real-time sneaker listings and purchases.

Stage II – Define the Technical Scope

The application uses several technologies, including APIs, PKI, SHA‑256, and SQL. I prioritized SQL because it directly handles sensitive user and transaction data stored in the database. SQL queries are critical for retrieving listings and processing purchases, making them a high‑risk area for injection attacks. Securing SQL operations ensures data integrity and prevents unauthorized access.

Stage III – Decompose the Application

The data flow begins when a user searches for sneakers. The app sends a query to the database, retrieves matching listings, and displays them to the user. This flow highlights exposure points where user input interacts with backend systems, creating opportunities for injection or data manipulation attacks.

Stage IV – Threat Analysis

Internal threats include SQL injection through poorly validated input fields and misconfigured API endpoints that expose internal data. External threats include session hijacking caused by insecure cookies or weak encryption, as well as credential‑stuffing attacks that exploit weak passwords.

Stage V – Vulnerability Analysis

Two major vulnerabilities were identified:

  • Lack of input validation and missing parameterized SQL queries, which increases the risk of SQL injection.
  • Weak session management that allows attackers to reuse stolen tokens.

Stage VI – Attack Modeling

The attacker’s primary goal is to compromise user data. Possible attack paths include:

  • Exploiting SQL injection to extract database records
  • Hijacking user sessions through insecure tokens
  • Using weak credentials to gain unauthorized access

Stage VII – Risk Analysis and Impact

To reduce risk, I identified four key security controls:

  • Implement parameterized queries and strict input validation to prevent SQL injection
  • Enforce multi‑factor authentication (MFA) for all user accounts
  • Use secure session management with HTTPS and short‑lived tokens
  • Apply continuous monitoring and logging to detect suspicious activity

Reflection

This activity demonstrated how the PASTA framework provides a structured, attacker‑focused approach to identifying risks in new applications. By analyzing business objectives, technical components, threats, vulnerabilities, and attack paths, I was able to recommend targeted controls that strengthen the app’s security posture before launch.
