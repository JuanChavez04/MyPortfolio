Lab 7 – Analyze a Vulnerable System

Course 5 - Assets, Threats, and Vulnerabilities

Overview

In this activity, I conducted a vulnerability assessment for a small e‑commerce business using guidance from NIST SP 800‑30 Rev. 1. The goal was to evaluate risks affecting the company’s publicly accessible database server and outline a remediation strategy to reduce exposure. This assessment demonstrates how cybersecurity analysts identify threats, determine likelihood and severity, and recommend controls to protect critical systems.

Scenario

The company stores customer and business data on a remote database server that has been publicly accessible since launch. Employees around the world regularly query the server to find potential customers. As a cybersecurity analyst, I recognized that leaving the database open to the public is a major vulnerability that increases the risk of data breaches, unauthorized access, and service disruption.

System Description

The system consists of a high‑performance Linux server with 128GB of memory and a MySQL database. It communicates with other servers over IPv4 and uses SSL/TLS for encrypted connections. Because it stores customer orders, payment records, and inventory data, the server is essential to business operations and must remain secure and available.

Scope

The vulnerability assessment covers a three‑month period from January to March 2026. The focus is on evaluating access controls and identifying risks associated with the database server. NIST SP 800‑30 Rev. 1 was used as the framework for analyzing threats, vulnerabilities, likelihood, and severity.

Purpose

The database server is critical to the business because it stores sensitive customer and operational data. Securing this server protects confidentiality, integrity, and availability. If the server were disabled or compromised, the business could lose access to essential information, interrupt sales, and suffer financial and reputational damage.

Risk Assessment

I evaluated several realistic threat scenarios based on NIST SP 800‑30 guidance. Each threat was scored using likelihood and severity values to determine overall risk.

Threat Sources and Events (NIST SP 800‑30)

NIST SP 800‑30 categorizes threat sources as human, technological, or environmental. For this assessment, the most relevant threat sources included:

  • Competitors attempting to exfiltrate sensitive information
  • Cybercriminals launching ransomware attacks
  • Insiders misusing administrative privileges

Threat events included data exfiltration, ransomware encryption, and unauthorized modification of records. These events directly impact confidentiality, integrity, and availability of the database.

Approach

I evaluated risks by considering the likelihood of each threat event and the severity of its impact on business operations. External attackers and insiders pose the highest risk because they can directly compromise sensitive data or disrupt operations. The chosen threats reflect common vulnerabilities in small business environments.

Remediation Strategy

Based on the assessment, I recommended several improvements to strengthen the security of the database server:

  • Implement multi‑factor authentication for all administrative accounts
  • Enforce least‑privilege access controls and role‑based permissions
  • Encrypt data in motion using TLS instead of SSL
  • Apply IP allow‑listing to restrict access to corporate locations
  • Conduct regular backups to mitigate ransomware impact
  • Use network segmentation and continuous monitoring to detect anomalies
  • Apply timely software updates and security patches

These controls reduce exposure to external attacks, prevent unauthorized access, and improve the overall resilience of the system.

Reference Framework

The assessment aligns with NIST SP 800‑30 Rev. 1, which provides structured guidance for identifying threat sources, evaluating likelihood and severity, and prioritizing remediation efforts.

Reflection

This activity strengthened my understanding of vulnerability assessments and how to apply NIST risk assessment principles in real-world scenarios. By identifying threats, scoring risks, and recommending targeted controls, I demonstrated how cybersecurity analysts help organizations reduce vulnerabilities and protect critical systems.
