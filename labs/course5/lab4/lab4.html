Lab 4 – Decrypt an encrypted message

Course 5 - Assets, Threats, and Vulnerabilities

Overview

In this lab, I practiced decrypting an encrypted message by using Linux commands, classical cipher techniques, and modern cryptographic tools. The activity required navigating directories, reading files, decoding a Caesar cipher, and using OpenSSL to decrypt an AES‑256‑CBC encrypted file. This process demonstrates how encryption and decryption support data security in real-world environments.

Task 1 – List the Contents of a Directory

I began by listing the contents of the /home/analyst directory. This revealed several important files, including:

  • Q1.encrypted – the encrypted file that needed to be restored
  • README.txt – a clue explaining that all data had been encrypted
  • caesar/ – a folder containing a hidden cipher file

Task 2 – Read the Contents of Files

I used cat to read the README.txt file, which explained that the encryption key could be recovered by solving a classical cipher. Inside the caesar directory, I found a hidden file named .leftShift3 containing text encoded with a Caesar cipher.

Task 3 – Decode a Classical Cipher

The hidden file used a Caesar cipher with a left shift of 3. I used the tr command to revert the ciphertext back to plaintext. The decoded message revealed the password needed to decrypt the main encrypted file.

Task 4 – Decrypt the Encrypted File

Using the recovered password, I executed the following OpenSSL command to decrypt the file:

openssl aes-256-cbc -pbkdf2 -a -d -in Q1.encrypted -out Q1.recovered -k ettubrate

This successfully restored the original file, Q1.recovered, which contained a confirmation message indicating that the decryption process was completed correctly.

Reflection

This lab demonstrated how classical and modern cryptography can work together in layered security challenges. I reinforced my skills in Linux navigation, file analysis, cipher decoding, and AES decryption. Understanding how to recover encrypted data is essential for cybersecurity analysts who may need to investigate incidents, restore corrupted files, or validate encryption processes.
