Lab 5 – Analyzing network layer communication

Course 3 - Connect and Protect: Networks and Network Security

Overview

In this lab, I analyzed DNS and ICMP traffic using packet data from a network protocol analyzer. The goal was to identify which network protocol was involved in a service interruption and determine whether the traffic patterns indicated a potential cybersecurity incident. This activity strengthened my understanding of how the Internet layer of the TCP/IP model handles packet delivery and how ICMP responses can reveal network issues or misconfigurations.

Tools Used

  • Network protocol analyzer logs (DNS & ICMP)
  • TCP/IP model analysis
  • Packet inspection techniques
  • Incident documentation

What I Learned

  • How DNS queries work: DNS uses UDP port 53 to resolve domain names into IP addresses.
  • How ICMP operates: ICMP is used for error reporting and diagnostics, such as “destination unreachable” messages.
  • How to identify abnormal traffic: Repeated DNS queries followed by ICMP port unreachable errors can indicate misconfigurations, outages, or malicious interference.
  • How to interpret packet logs: Timestamps, source/destination IPs, ports, and protocol types reveal the sequence of events during a network issue.
  • How to document findings: I practiced summarizing network behavior and identifying which protocol was responsible for the interruption.

Scenario

A user attempted to access yummyrecipesforme.com, but the website failed to load. As a cybersecurity analyst, I reviewed DNS and ICMP packet logs to determine what happened. The logs showed repeated DNS queries to a DNS server, followed by ICMP responses indicating that UDP port 53 was unreachable. My task was to identify the protocol involved and explain what the traffic revealed about the incident.

My Analysis

The packet logs showed multiple DNS queries from the user’s machine to the DNS server 203.0.113.2, attempting to resolve yummyrecipesforme.com. Each query was followed by an ICMP message stating that UDP port 53 was unreachable. This indicates that the DNS server was either offline, misconfigured, or intentionally blocking DNS requests.

Because DNS relies on UDP port 53, the ICMP “port unreachable” responses confirm that the issue occurred at the Internet layer of the TCP/IP model. Without a valid DNS response, the user’s machine could not obtain the IP address of the website, resulting in a failed connection.

Based on the traffic pattern, the protocol involved in the incident was ICMP, which reported the failure of DNS (UDP port 53). This type of behavior can indicate a network outage, firewall misconfiguration, or potential malicious interference with DNS resolution.
