lab 4 – Use the NIST cybersecurity framework to respond to a security incident

Course 3 - Connect and Protect: Networks and Network Security

Overview

In this lab, I analyzed a Denial-of-Service (DoS) attack using the NIST Cybersecurity Framework (CSF). I reviewed an incident involving ICMP flooding caused by a misconfigured firewall and documented the event using the five NIST CSF functions: Identify, Protect, Detect, Respond, and Recover. This activity helped me understand how to structure an incident report, evaluate root causes, and propose improvements to strengthen an organization’s security posture.

Tools Used

  • NIST Cybersecurity Framework (CSF)
  • Incident response documentation
  • Firewall and network traffic analysis
  • SIEM and log monitoring concepts

What I Learned

  • How to apply the NIST CSF: I learned how each function (Identify, Protect, Detect, Respond, Recover) guides the lifecycle of incident handling and long-term security improvement.
  • Root cause analysis: Misconfigured firewalls can allow malicious traffic—such as ICMP floods—to bypass protections and disrupt services.
  • Importance of monitoring: SIEM alerts, IDS/IPS logs, and traffic analysis are essential for detecting abnormal patterns early.
  • Incident response workflow: Blocking malicious traffic, isolating systems, restoring services, and documenting actions are critical steps.
  • Recovery and improvement: Updating baselines, auditing configurations, and training staff help prevent similar incidents in the future.

Scenario

A company experienced a two-hour outage caused by a DoS attack in which an external actor flooded the network with ICMP packets. The firewall was misconfigured and failed to block the traffic, allowing the attack to overwhelm internal systems. As a security analyst, I was tasked with analyzing the incident using the NIST CSF, documenting what happened, and recommending improvements to prevent future disruptions.

My Analysis

Using the NIST CSF, I broke down the incident into the five core functions:

Identify: The attack was a DoS event using ICMP packets. Affected systems included the internal network, DNS services, and the firewall. The root cause was a misconfigured firewall that allowed ICMP traffic to pass unchecked.

Protect: To prevent recurrence, the organization should properly configure firewall rules, maintain secure baseline configurations, apply patch updates, and implement multi-factor authentication for administrative access. Regular rule reviews and documentation updates are essential.

Detect: Detection can be improved by using SIEM tools to monitor for abnormal ICMP patterns, setting alerts for traffic spikes, and reviewing IDS/IPS logs to identify suspicious activity early.

Respond: The response included blocking incoming ICMP traffic, isolating affected systems, restoring critical services, analyzing logs to confirm the attack source, and notifying the incident response team. These actions helped contain the attack and restore functionality.

Recover: Recovery steps included restoring all network services, verifying firewall configurations, updating baseline documentation, conducting a post-incident review, and scheduling regular audits and staff training to prevent similar incidents in the future.

This structured approach demonstrated how the NIST CSF helps organizations manage incidents effectively and continuously improve their security posture.
