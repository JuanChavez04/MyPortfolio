Lab 1 – Analyze Network Attacks

Course 3 - Connect and Protect: Networks and Network Security

Overview

This lab focused on analyzing a real‑world network interruption caused by a malicious actor. Using packet logs and attack indicators, I identified the type of attack, explained how it disrupted the website, and interpreted TCP handshake behavior during normal and abnormal traffic. This activity strengthened my understanding of network attacks, TCP/IP communication, and how to recognize signs of a Denial of Service attack in packet captures.

Tools Used

  • Network protocol analyzer logs (TCP/HTTP)
  • Wireshark‑style packet interpretation
  • Attack pattern recognition
  • TCP/IP model analysis
  • Incident reporting and documentation skills

What I Learned

  • How to identify abnormal TCP behavior such as repeated SYN packets without completing the handshake.
  • How a SYN flood attack overwhelms a server by filling its connection queue.
  • How to distinguish legitimate traffic from malicious traffic using packet logs.
  • How to interpret RST, ACK, 504 Gateway Timeout, and other error indicators.
  • How to write a clear cybersecurity incident report explaining the attack, its cause, and its impact.
  • How DoS attacks degrade availability and prevent users from accessing services.

Scenario

A customer reported that the company website was timing out and failing to load. As a cybersecurity analyst, I was tasked with reviewing TCP/HTTP logs to determine the cause of the interruption. The logs showed a mix of normal employee traffic and suspicious repeated SYN packets from an unknown external IP address. My goal was to identify the attack type, explain how it disrupted the website, and document the findings in an incident report.

My Analysis

I examined the TCP logs and found that the attacker at IP 203.0.113.0 repeatedly sent SYN packets to the web server on port 443 without completing the handshake. This created numerous half‑open connections, consuming server resources and preventing legitimate users from connecting.

Normal traffic (highlighted in green) showed the expected SYN → SYN/ACK → ACK sequence, followed by HTTP GET requests and successful responses. However, as the attack intensified, the server began responding with RST, ACK packets and 504 Gateway Timeout errors, indicating it could no longer process legitimate requests.

Based on the traffic pattern, the repeated SYN packets, and the server’s inability to complete handshakes, I concluded that this was a TCP SYN Flood DoS attack. I documented the attack, explained the handshake disruption, and described the negative impact on website availability in the incident report.
