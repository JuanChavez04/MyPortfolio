Lab 7 – Use Linux commands to manage file permissions

Course 4 - Tools of Trade: Linux and SQL

Overview

In this lab, I examined and modified file and directory permissions in a Linux environment. These skills are essential for configuring user authorization and ensuring that sensitive files are only accessible to the correct users. I used ls -l to inspect permissions and chmod to correct overly permissive access settings based on the principle of least privilege.

Task 1 – Check Permissions for Files in a Directory

I used the ls -l command to review the permissions of all files in the /home/researcher2/projects directory. This allowed me to identify files that granted unnecessary read or write access to group or other users.

Task 2 – Identify and Correct Incorrect Permissions

Several files had permissions that violated the principle of least privilege. I used chmod to remove unnecessary access:

  • project_k.txt: removed group and other write access
  • project_m.txt: removed group read access
  • project_r.txt: removed group write and other read access
  • project_t.txt: removed group write and other read access

Task 3 – Correct Permissions on a Hidden File

The hidden file .project_x.txt had insecure permissions that allowed group users to write to the file. I removed group write access to ensure only the owner could modify it.

Task 4 – Restrict Access to a Directory

The drafts/ directory allowed group users to execute (enter) the directory. I restricted group and other access to ensure only the owner could access or modify the directory contents.

Reflection

This lab strengthened my understanding of Linux file permissions and how to manage them effectively. I practiced interpreting permission strings, identifying security risks, and applying the principle of least privilege. These skills are essential for securing file systems and preventing unauthorized access in professional environments.
